# Windows Exporter

`windows_exporter` runs as a Windows service on `Elessa-Essome`
(`penda.elessa.internal`, Windows 11 Pro) and is scraped by the in-cluster Prometheus
from kube-prometheus-stack. It is the only static scrape target in the repo.

| Item        | Value                                                                     |
| ----------- | ------------------------------------------------------------------------- |
| Host        | `penda.elessa.internal` (Windows hostname `Elessa-Essome`)                |
| Endpoint    | `http://penda.elessa.internal:9182/metrics`                                |
| Exporter    | `prometheus-community/windows_exporter` 0.31.9 (MSI, `LocalSystem`)        |
| Service     | `windows_exporter` (Automatic), `C:\Program Files\windows_exporter`        |
| Prometheus  | job `windows-exporter`, instance label `penda.elessa.internal:9182`        |
| Manifests   | `fluxcd/infrastructure/monitoring/kube-prometheus-stack/`                 |
| Dashboard   | `dashboards/windows-exporter.json` → ConfigMap `windows-exporter-dashboard` |
| Grafana     | <https://grafana.teamg.app> (sidecar picks up `grafana_dashboard: "1"`)    |

## Installation

The MSI is pinned and installed over SSH with an elevated PowerShell session:

```powershell
$url = 'https://github.com/prometheus-community/windows_exporter/releases/download/v0.31.9/windows_exporter-0.31.9-amd64.msi'
$msi = Join-Path $env:TEMP 'windows_exporter-0.31.9-amd64.msi'
curl.exe -fL -o $msi $url
(Get-FileHash -Algorithm SHA256 $msi).Hash  # 1e8a3898e8febaa475e008ffd2e729e1bef84ecbcb6875910546ee0798e96126
$collectors = 'cpu,logical_disk,memory,net,os,physical_disk,service,system,update,gpu'
$args = "/i `"$msi`" /qn /norestart ENABLED_COLLECTORS=`"$collectors`" ADDLOCAL=FirewallException LISTEN_PORT=9182"
Start-Process msiexec.exe -ArgumentList $args -Wait -PassThru
```

Defaults are listed explicitly instead of using the `[defaults]` placeholder:
MSI formatted fields may substitute bracketed values. The generated
`config.yaml` in the install directory is empty; collector selection lives in
the service command line.

The `update` collector runs offline with a six-hour cache by default, so it
does not add latency to scrapes. The `gpu` collector sees both the NVIDIA RTX
5090 and the AMD Radeon graphics.

## Firewall

`ADDLOCAL=FirewallException` creates the inbound rule `windows_exporter`. It is
scoped to the Talos node network, because Prometheus pods are SNAT'd to their
node IP by Cilium (`enable-ipv4-masquerade=true`):

```powershell
Get-NetFirewallRule -DisplayName windows_exporter |
  Get-NetFirewallAddressFilter |
  Set-NetFirewallAddressFilter -RemoteAddress '10.25.25.0/24'
```

Leave the allow-list at the whole node subnet: Prometheus may be rescheduled
to any of `beast` (`.172`), `rpi5` (`.186`) or `hedy` (`.191`).

## Prometheus and Grafana

`prometheus.prometheusSpec.additionalScrapeConfigs` in `values.yml` defines the
job with `scrape_timeout: 30s`. The hostname target is overridden to
`instance="penda.elessa.internal:9182"` so series are readable; the
`os: windows` label marks the target. No ServiceMonitor, secret or TLS config
is involved.

`dashboards/windows-exporter.json` is a classic Grafana dashboard generated by
`configMapGenerator` with the `grafana_dashboard: "1"` label, so the
kube-prometheus-stack dashboard sidecar imports it. Panels cover uptime,
pending updates, stopped services, GPUs, CPU, memory, disk, network and GPU
VRAM. Queries select on `job="windows-exporter"` and the `instance` template
variable. Upstream `contrib/dashboard/*.json` is Grafana v2 resource schema
and is not sidecar-compatible, hence the local dashboard.

## Verification

```sh
# host
ssh penda.elessa.internal 'curl.exe -s http://127.0.0.1:9182/metrics | findstr /B /C:"windows_exporter_collector_success"'
# expected: value 1 for all ten collectors

# from the cluster (throwaway pod)
kubectl run winprobe --image=busybox:1.36 --restart=Never --rm -it -- \
  sh -c 'wget -qO- -T 15 http://penda.elessa.internal:9182/metrics | head'

# after Flux reconciles infra-monitoring
curl -s https://prometheus.teamg.app/api/v1/targets | grep windows-exporter
```

## Upgrades and troubleshooting

- Upgrade by downloading the new MSI and rerunning the same `msiexec` command.
  Installers before 0.32.2 do not remember parameters, so all properties must
  be passed again. `winget upgrade Prometheus.WindowsExporter` will not carry
  the collector list or firewall settings. This version is not tracked by
  Renovate (it lives outside the repo).
- `windows_exporter_collector_success{collector="..."} == 0` identifies a
  failing collector. The `update` collector requires the Windows Update service
  (`wuauserv`) to be running; a failed update search fails that collector.
- If scrape targets go `DOWN`, check the firewall allow-list still contains
  the node IP that Prometheus egresses from, and that the service is running.
- No `PrometheusRule` alerts for `windows_*` metrics exist yet; the chart's
  default node-exporter rules only match Linux `node_*` metrics.
